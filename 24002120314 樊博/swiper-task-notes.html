提示词工程师：让 AI 听懂需求两轮迭代 · 需求拆解 → 提示词精确性 → 输出验证

需求原文：生成 new Swiper('#wySw4', {...}) 配置——① 无缝循环 ② 3.2 秒自动翻页且手动操作后不停止 ③ 圆点分页器可点击 ④ 初始效果为 cube。

需求拆解表（动手写提示词之前先做）

需求对应的参数写法容易漏的点
① 无缝循环loop: true写成字符串 'true'，或者干脆没写
② 3.2 秒自动翻页、手动后不停autoplay: { delay: 3200, disableOnInteraction: false }只写 autoplay: true（默认 3 秒且一拖就停）；把 3.2 秒写成 delay: 3.2
③ 圆点分页器可点击pagination: { el: '#wyPag4', clickable: true }漏 el（圆点不出现）；漏 clickable（圆点不能点）
④ 初始效果 cubeeffect: 'cube'只写了 effect，没考虑 cube 需要的 cubeEffect 默认值是否够用
第 1 轮 · 提示词（写得太笼统）
帮我用 Swiper 初始化 #wySw4，要能循环，自动播放，底部有圆点，初始效果用 cube。

AI 回答（摘录）：

var swiper4 = new Swiper('#wySw4', {
  loop: true,
  autoplay: true,
  pagination: { el: '#wyPag4' },
  effect: 'cube'
});
一句话结论：四条需求只满足了 ①④ —— autoplay: true 变成默认 3 秒且一拖动就永久停止，pagination 漏了 clickable 圆点不能点，也没有 3.2 秒的说法。粘贴进页面后：自动播放 3 秒就翻、拖一下就再也不自动翻，圆点点不动。
第 2 轮 · 提示词（把需求写成可验收的条目）
请生成 Swiper 11 的初始化配置 new Swiper('#wySw4', {...})，逐条满足下列要求，参数名必须准确，不要省略不要改写成别的写法：
1）loop 为布尔值 true，实现无缝循环；
2）autoplay 用对象写法，delay 为数字 3200（单位毫秒），disableOnInteraction 必须为 false，保证用户手动滑动后自动播放继续；
3）pagination 用对象写法，el 传入 '#wyPag4'，clickable 为 true；
4）effect 传入字符串 'cube' 作为初始效果；
5）另外加上 speed: 800，切换动画 800 毫秒。
请只输出一段可直接粘贴的 JS 代码，并在每行后加中文注释说明它对应哪一条要求。

AI 回答（正式采用，即成品页中的配置）：

var wySw4 = new Swiper('#wySw4', {
  loop: true,                                          // 需求① 无缝循环
  speed: 800,                                          // 需求⑤ 切换动画 800ms
  effect: 'slide',
  autoplay: { delay: 3200, disableOnInteraction: false }, // 需求② 3.2 秒一翻，手动后继续
  pagination: { el: '#wyPag4', clickable: true }        // 需求③ 圆点可点击
});
验证结论（浏览器实测，F12 控制台无报错）：
· 需求①：翻到第 6 张继续往后翻，回到第 1 张 → 通过；
· 需求②：什么都不点，约 3.2 秒翻一次；按住拖动松手后仍继续自动翻 → 通过；
· 需求③：底部 6 个圆点，点第 4 个直接跳到第 4 张 → 通过；
· 需求④：成品页按任务四要求以 slide 起步，cube 由「cube」按钮实时切换验证，切后呈 3D 立方体 → 通过。

复盘三问（答辩用）

  • 第一版漏了什么？漏了「3.2 秒」这个数值和「手动后不停」这个行为，还漏了 clickable；本质是把"自动播放""圆点"当成了一个开关，而 Swiper 里它们是对象配置。
  • 第二轮怎么"说清楚"的？把四句话拆成五条可验收的条目，明确 参数名 + 值的类型 + 单位 + 布尔值，并禁止改写成别的写法。
  • AI 第一次错在哪？autoplay: true 等价于默认 3 秒且 disableOnInteraction 默认 true，与需求②直接冲突；pagination 少了 clickable: true。

creative 仿写：课堂没讲的第 7 种效果creativeEffect 的 prev / next transform

思路：creative 不是预设动画，而是由我们自己"描述"每张非当前卡片的位置。核心就是把 prev（已经翻过去、停在左边的那张）和 next（还没轮到、等在右边的那张）各写一组变换参数，Swiper 负责在两者之间做补间。

effect: 'creative',
creativeEffect: {
  limitProgress: 2,                        // 一张卡片最多按几段位移去计算
  prev: {                                  // 上一张（停在左侧）
    shadow: true,
    translate: ['-28%', 0, -400],          // 左移 28%、不进不退、沿 Z 轴后退 400px
    rotate: [0, 0, -18],                   // 绕 Z 轴逆时针转 18°，像斜插在片架上
    scale: 0.82,                           // 缩小到 82%
    opacity: 0.65
  },
  next: {                                  // 下一张（等在右侧）
    translate: ['100%', 0, 0],             // 停在右侧一屏之外
    scale: 1.12,                           // 放大到 112%，进场时有"推近"感
    rotate: [0, 0, 0],
    opacity: 1
  }
}

用我自己的话说：prev / next 的 transform 各控制什么？

  • prev：当前这张的前一张翻走以后停在哪儿、什么姿态。我把它写成「缩小 82% + 左移 28% + 后退 400px + 逆时针倾 18° + 半透明」，于是它像一张被推到片架左侧的旧胶片，既退到后面又不抢戏。
  • next：当前这张的后一张在轮到它之前躲在哪儿、多大。我写的是「停在右侧 100% 处、放大 112%」，这样它切进来时是从右边"压近"进画，形成电影选片墙那种一推一收的节奏。
  • 两者共同决定了一组"三态"：左（缩小倾斜退后）— 中（正位）— 右（放大待入）。中间那张用的是默认值，不需要写。
验证结论：点「creative 电影墙」按钮后，当前张居中正放，左边一张缩小并带倾斜退后、右侧一张放大待入，圆点与 3.2 秒自动播放照常工作，控制台无报错 → 通过。

答辩预答

  • transform 里的百分号相对谁？相对轮播容器（slide 自身宽度），不是相对照片本身；所以 -28% 是"往左挪出三成箱体宽的位移量"，换屏幕尺寸也能等比变化。
  • 改一个数值让卡片转 20 度怎么改？把 prev.rotate 的第三个值改成 -20（顺时针正数、逆时针负数）：rotate: [0, 0, -20]。旋转轴是 Z 轴（垂直屏幕向外），所以看起来是"在纸面上转"。

② 课堂上没讲过的能力：keyboard 键盘控制

四个额外能力里我选 keyboard：改配置就能用，不需要改结构，演示时"按一下方向键就翻页"最直观。

keyboard: {
  enabled: true,          // 开启键盘控制
  onlyInViewport: true    // 轮播不在视口内时不响应，避免用户滚到别处还在翻页
}

用法：先用鼠标点一下轮播图（容器获得焦点），再按 ← / →。注意它只在演示四上开启，前三个演示保持纯鼠标/触摸操作。

AI 关键对话记录（提示词 + 往返）

往返 1 · 问 creative 怎么用
Swiper 11 里 effect: 'creative' 除了 prev / next 还能写什么？我想做"上一张缩小左移带角度、下一张放大右移进场"的电影选片墙效果。

AI 回答要点：creativeEffect 支持 prev / next / limitProgress / perspective / progressMultiplier；每个方向可写 translate（数组，支持 %、px）、rotate、scale、opacity、origin、shadow。给出 translate: ['-28%', 0, -400] + rotate: [0,0,-18] + scale: 0.82 的写法。

我的核对：scale 与 opacity 确实在 prev 里生效；旧版只有 translate，新版才有 scale/opacity，所以要确认用的是 Swiper 11。

往返 2 · 追问 transform 的百分号
translate 里的 -28% 是相对图片还是相对轮播容器？我把 rotate 改成 [0, 0, -20] 会发生什么？

AI 回答要点：百分比相对 slide 自身尺寸（也就是容器可见宽度），不是相对内部 img；rotate 三个值依次对应 X / Y / Z 轴，Z 轴是屏幕法线方向，改第三个值就是"在纸面上转"。我据此把 -18° 微调到 -18°，答辩时改成 -20° 现场演示。

往返 3 · 键盘控制
Swiper 11 加键盘控制要哪些配置？为什么我加了没反应？

AI 回答要点：需要 keyboard: { enabled: true }，并且轮播容器必须获得焦点（a11y 会给容器加 tabindex，所以先点一下或 Tab 过去）；在 iframe 里或容器无焦点时按方向键无效。补充 onlyInViewport: true 可避免页面外的轮播也跟着翻。

答辩四连问 · 我的回答

  • 这段代码什么意思？wySw4Options(fx) 把演示四的完整配置收在一个函数里，参数 fx 决定 effect，只有 creative 时才额外挂上 creativeEffect；按钮点击时先清高亮、再 destroy(true, true) 销毁旧实例、最后用新配置 new Swiper 重建——因为 Swiper 的 effect 模块是在实例化时装配的，运行中只改参数不会重新装载。
  • AI 第一次给的哪里不对、改了什么？第一次给的 autoplay: true 会一拖就停，且没有 3.2 秒；另外直接 swiper.params.effect = 'cube' 想"热改"效果，实际无效，必须重建实例。我改成对象写法 + destroy/rebuild。
  • 新参数的作用？keyboard.enabled 打开键盘监听，onlyInViewport 限制只在轮播可见时响应；creativeEffect.prev/next 描述非当前卡的位移/旋转/缩放，limitProgress 控制最多按几段位移计算。
  • 现场把 delay 改成指定值并解释预期变化？例如把 delay: 3200 改成 delay: 1000：页面上表现为每张停留时间由约 3.2 秒缩短到 1 秒，翻页明显变快，但切换动画时长仍由 speed: 800 决定，不受影响（delay 管"停留"，speed 管"过渡"）。
